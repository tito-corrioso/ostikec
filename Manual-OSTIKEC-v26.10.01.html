PARTE 1 — MANUAL DE USUARIO

Guía de uso de OSTIKEC para negocios y usuarios finales

¿Qué es OSTIKEC?

OSTIKEC es un sistema de tickets electrónicos con código QR diseñado para negocios y empresas que necesitan entregar comprobantes verificables de forma rápida, segura y sin depender de internet.

Cada vez que un cliente compra un producto, reserva un asiento, contrata un servicio o recibe cualquier tipo de comprobante, tu equipo puede generar un ticket con su código QR único. Ese ticket se imprime, se comparte por WhatsApp, se guarda como imagen o se muestra en pantalla. Días después, cuando el cliente presente el ticket, cualquier dispositivo autorizado puede escanear el código y verificar en segundos que es auténtico.

Beneficios para tu negocio

Profesionaliza tu operación. Con OSTIKEC, cada venta queda respaldada por un comprobante verificable. Tus clientes reciben un ticket con la imagen de tu marca, el nombre de tu negocio y los datos completos del servicio.

¿Por qué elegir OSTIKEC?

  • Funciona sin internet. No necesitas conexión para generar o validar tickets. Todo sucede dentro del dispositivo.
  • Seguridad real contra falsificaciones. Cada código QR va cifrado y firmado digitalmente. Si alguien intenta alterar un dato o inventar un ticket, la validación fallará.
  • Verificación de emisor. Cada ticket guarda internamente el teléfono del dispositivo que lo emitió. Al validarlo, se muestra junto a los datos. Así sabrás con certeza qué cuenta generó cada comprobante.
  • Multi-negocio. Puedes manejar varios negocios o servicios desde una misma instalación. Cada uno con su propio nombre, datos de servicio y etiquetas personalizadas.
  • Sin contacto físico ni hardware extra. Solo necesitas un teléfono Android. Nada de lectores costosos ni impresoras especiales.
  • Reportería automática. El desarrollador recibe informes periódicos sobre accesos y tickets generados, lo que permite detectar cualquier uso indebido de licencias.
  • Revocación remota. Si tu licencia es comprometida, puede ser bloqueada de forma automática para proteger tu operación.
Ideal para: teatros, cines, eventos, conciertos, festivales, agencias de viaje, ómnibus y transporte, escuelas, academias, rifas, clubes, gimnasios, restaurantes, alquileres, servicios profesionales, facturación simple y cualquier negocio que necesite un comprobante verificable.

  2. Apunta la cámara al código del ticket. También puedes subir una imagen del código desde la galería.

PARTE 2 — MANUAL TÉCNICO

Arquitectura, lógica interna y seguridad del sistema

Este manual está dirigido al desarrollador o mantenedor de la aplicación. Contiene detalles del funcionamiento interno, la estructura del código y las consideraciones de seguridad. Se recomienda no compartirlo con usuarios finales. Los datos sensibles (tokens, URLs, claves) aparecen censurados.

Arquitectura de archivos

OSTIKEC está construido como una aplicación web empaquetada como APK. No hay backend propio: toda la lógica corre en el cliente y la única comunicación externa es opcional (Telegram).

Flujo de la aplicación

Arranque

  1. Se cargan las librerías y el estilo.
  2. El DOM se inicializa y cada archivo registra sus propios listeners.
  3. La pantalla 1 (login) aparece activa.
  4. Si existe una sesión guardada en localStorage y la huella del dispositivo coincide, se salta directo a la pantalla correspondiente.
  5. Si bloqueo.js está presente, se descarga la lista negra en segundo plano.

Inicio de sesión

  1. El usuario escribe teléfono y licencia.
  2. El sistema normaliza el teléfono (quita +53 y 53 al inicio si sobran dígitos).
  3. Se busca al usuario en USUARIOS_AUTORIZADOS comparando teléfono y licencia en mayúsculas.
  4. Si coincide, se guarda la sesión (tel, tipo, huella, fecha) y se muestra la pantalla correspondiente.
  5. Si bloqueo.js detecta que el usuario está en la lista negra, se muestra la pantalla de bloqueo y se cierra la sesión.

Generación de un ticket

  1. El usuario rellena los campos del formulario.
  2. Se valida que no haya campos vacíos y que el asiento sea numérico.
  3. Se construye un objeto {f, n, t, a, i}.
  4. extras.js intercepta construirContenidoQR y añade el teléfono emisor como e.
  5. El JSON resultante se cifra con Base64 + desplazamiento variable.
  6. Se calcula la firma SHA-256 de clave_secreta + json y se toman los primeros 12 caracteres.
  7. El QR resultante tiene la forma OTK1|<cifrado>|<firma>.
  8. Se dibuja el ticket completo en un canvas con el logo, los datos, el QR y la fecha de emisión.
  9. Si hay un negocio activo, se añaden su nombre arriba a la derecha y sus datos de servicio abajo del QR.
  10. panel.js envía un aviso a Telegram con la huella del dispositivo y el nombre del negocio (o "(Sin negocio asignado)").

Validación de un ticket

  1. El usuario abre el lector QR desde la pantalla del creador o del validador.
  2. Se captura el código con la cámara o desde un archivo.
  3. Se lee el contenido del QR y se divide por |.
  4. Se comprueba que empiece por OTK1.
  5. Se descifra la parte del medio y se recalcula la firma.
  6. Si la firma coincide, el ticket es válido. Si no, se marca como falsificado o alterado.
  7. Se muestran los datos y, si existe, el teléfono emisor.
  8. Las filas 4 y 5 se rotulan siempre como Campo 4 y Campo 5 (interceptado por extras.js).

Sesión y huella del dispositivo

Huella del dispositivo

Es un hash de 16 caracteres calculado a partir de características del teléfono:

function huellaDispositivo() {
  const partes = [
    navigator.userAgent,
    navigator.language,
    navigator.platform || '',
    screen.width, screen.height, screen.colorDepth,
    window.devicePixelRatio,
    new Date().getTimezoneOffset()
  ];
  return sha256Hex(partes.join('|')).substring(0, 16);
}
Limitación conocida: dos teléfonos idénticos con la misma configuración pueden generar la misma huella. La huella no es un identificador único garantizado, pero sirve como referencia para detectar cambios de dispositivo en la mayoría de casos.

Sesión guardada

Al iniciar sesión correctamente, se guarda en localStorage bajo la clave ostikec_sesion:

{
  "tel": "54XXXXXX",
  "tipo": "creador",
  "huella": "a1b2c3d4e5f6a7b8",
  "fecha": 1759156200000
}

La próxima vez que se abra la app, si la huella coincide con la actual, se salta el login.

Cifrado y firma digital

Cifrado reversible

Los datos del ticket se serializan como JSON y se cifran con un esquema propio: Base64 + desplazamiento variable sobre el alfabeto Base64. El resultado sigue siendo Base64 válido, así que el QR nunca se rompe.

function cifrarCadena(textoPlano) {
  const base64 = btoa(unescape(encodeURIComponent(textoPlano)));
  let salida = '';
  for (let i = 0; i < base64.length; i++) {
    const ch = base64[i];
    if (ch === '=') { salida += '='; continue; }
    const indice = ALFABETO_B64.indexOf(ch);
    salida += ALFABETO_B64[(indice + CLAVE_CIFRADO + i * 3) % 64];
  }
  return salida;
}

Firma SHA-256

Se calcula sha256Hex(CLAVE_SECRETA + json) y se toman los primeros 12 caracteres en hexadecimal. Esa firma viaja en el QR junto a los datos cifrados.

OTK1|<cifrado>|<firma_de_12_caracteres>

Al validar, se recalcula la firma con los mismos datos y se compara. Si no coincide, el ticket es rechazado.

Clave secreta: TU_CLAVE_SECRETA_AQUI. Si se cambia, todos los tickets generados antes dejan de ser válidos. Anótala en un lugar seguro.

Reporte a Telegram

Cuando panel.js está presente, la aplicación envía avisos a un chat de Telegram usando un bot. Esto permite al desarrollador estar informado de todos los accesos y tickets generados.

Cómo se envían los mensajes

Se utiliza el truco de crear un Image con la URL de la API de Telegram. Esto evita los problemas de CORS en el WebView.

const img = new Image();
img.src = 'https://api.telegram.org/bot<TOKEN>/sendMessage?' +
          'chat_id=<CHAT_ID>&text=' + encodeURIComponent(texto);

Datos que se envían

En cada login:

  • Huella del dispositivo
  • Teléfono y licencia usados
  • Tipo (creador o validador)
  • Fecha y hora

En cada ticket generado:

  • Huella del dispositivo
  • Nombre del negocio (o "(Sin negocio asignado)")
  • Fecha y hora
Cola de reintentos: si no hay internet, los mensajes se guardan en localStorage y se reintentan en la próxima apertura.

Kill switch remoto

El archivo bloqueo.js permite revocar licencias de forma remota sin recompilar el APK.

Cómo funciona

  1. Al abrir la aplicación, se descarga un archivo blocked.json alojado en GitHub.
  2. Se guarda en caché local (localStorage).
  3. Al intentar iniciar sesión, se comprueba si el teléfono y la licencia están en la lista.
  4. Si coinciden, se muestra una pantalla de "ACCESO BLOQUEADO" y se cierra la sesión.

Formato de blocked.json

{
  "actualizado": "2026-10-01",
  "bloqueados": [
    {
      "telefono": "54XXXXXX",
      "licencia": "OT-CXXX-XX-X",
      "motivo": "Licencia revocada",
      "fecha": "2026-10-01"
    }
  ]
}
Cómo revocar una licencia: añade una entrada en blocked.json en el repositorio, súbela a GitHub, y en la próxima apertura con conexión el dispositivo bloqueado descargará la lista y se bloqueará.

Operaciones comunes

Cómo añadir una nueva licencia

  1. Abre index.html en GitHub.
  2. Busca USUARIOS_AUTORIZADOS.
  3. Añade una línea con el teléfono, la licencia y el tipo (creador o validador).
  4. Guarda los cambios.
  5. Vuelve a comprimir el ZIP y súbelo a AppMint.
  6. Genera un nuevo APK y distribúyelo.

Cómo bloquear una licencia

  1. Abre blocked.json en GitHub.
  2. Añade una entrada con teléfono, licencia y motivo.
  3. Guarda los cambios.
  4. En la próxima apertura con conexión, el dispositivo afectado descargará la lista y se bloqueará.

Cómo regenerar el token de Telegram

  1. Abre Telegram y busca @BotFather.
  2. Escribe /mybots y elige tu bot.
  3. Selecciona "API Token" y luego "Revoke current token".
  4. BotFather te dará un token nuevo. Cópialo.
  5. Reemplaza el valor en panel.js.
  6. Sube el ZIP actualizado a AppMint y regenera el APK.

Cómo cambiar la clave secreta

Cambiar la clave secreta invalida todos los tickets generados antes del cambio. Solo debe hacerse si la clave fue comprometida, y aceptando que los tickets viejos dejarán de validar.
  1. Abre index.html.
  2. Busca CLAVE_SECRETA.
  3. Cámbiala por un valor nuevo, largo y aleatorio.
  4. Regenera el APK.

Cómo compilar el APK

  1. Comprime en un ZIP: index.html, extras.css, extras.js, panel.js, bloqueo.js, qrcode.js, html5-qrcode.min.js.
  2. Entra a AppMint (o la plataforma de empaquetado que uses).
  3. Selecciona el modo "ZIP to APK" / "Offline ZIP".
  4. Sube el ZIP y configura el nombre, el paquete y el ícono.
  5. Genera el APK y descárgalo.
  6. Instálalo en los dispositivos autorizados.

Limitaciones conocidas

  • Un usuario con conocimientos técnicos podría descompilar el APK y ver las claves. La ofuscación del código mitiga parcialmente este riesgo.
  • Si un atacante conoce la clave secreta, puede generar tickets válidos.
  • Si dos dispositivos idénticos comparten huella, el sistema de bloqueo por huella no los distingue.
  • Si un usuario bloqueado nunca se conecta a internet, no descargará la lista negra actualizada.

Recomendaciones

  • No compartir el manual.html con usuarios finales.
  • Mantener la clave secreta y el token de Telegram fuera de cualquier documento compartido.
  • Revisar periódicamente los avisos de Telegram para detectar patrones anómalos.
  • Regenerar el token de Telegram si en algún momento se sospecha que fue comprometido.
  • Considerar la ofuscación del código antes de distribuir el APK a terceros.
